# AKS + custom CRD + operator

End-to-end tutorial: provision an AKS cluster, design and register a custom
`WebApp` CRD, write the Go controller (operator) that reconciles it, ship the
operator's image through ACR, and run it on the cluster. Separate from
[`k8s/aks_setup`](../aks_setup) (which is about standing up an app on AKS via
Helm) and from [`k8s_explorer/docs/crds-and-operators.md`](../k8s_explorer/docs/crds-and-operators.md)
(which explains *other people's* CRDs — KServe, Kargo, Argo Workflows). This
folder is about building your own from scratch.

## What you end up with

A `WebApp` custom resource:

```yaml
apiVersion: webapp.platformlab.dev/v1alpha1
kind: WebApp
metadata:
  name: hello-webapp
spec:
  image: nginxdemos/hello:plain-text
  replicas: 2
  port: 80
```

...and a controller Pod that watches for `WebApp` objects and continuously
reconciles a matching Deployment + Service for each one — the same
watch-reconcile pattern every real operator (cert-manager, KServe, Kargo)
uses, at the smallest scale that still teaches the whole mechanism.

## Layout

- [`infra/main.tf`](./infra/main.tf) — Terraform for the AKS cluster + ACR
  this tutorial runs against, following the same pattern as
  `k8s/aks_setup/minimul_aks_002/infra/main.tf` but in its own resource group
  so it can be created/destroyed independently.
- [`operators/`](./operators) — every operator implementation built in this
  tutorial, side by side; see [`operators/README.md`](./operators/README.md)
  for what each one is and how they compare.
  - [`webapp-operator/`](./operators/webapp-operator) — the Kubebuilder
    project. `api/v1alpha1/` and `internal/controller/` are hand-written for
    this tutorial; everything else (`go.mod`, `config/crd`, `config/rbac`,
    `config/manager`, the `Makefile`) is generated by running the commands in
    `docs/03-scaffold-with-kubebuilder.md` — see that doc for why those
    aren't checked in by hand.
  - [`webapp-operator-python/`](./operators/webapp-operator-python) — a
    `kopf` reimplementation of the same `WebApp` CRD, for comparing Go
    against Python (see `docs/qna.md`).
  - [`greeting-operator/`](./operators/greeting-operator) — a second,
    smaller CRD (`Greeting` → `ConfigMap`) built from scratch by hand.
- `docs/` — the tutorial itself, read in order:

  1. [`01-cluster-and-registry.md`](./docs/01-cluster-and-registry.md) — apply
     the Terraform, get credentials, confirm the cluster and ACR are ready.
  2. [`02-crd-design.md`](./docs/02-crd-design.md) — what a CRD actually is,
     and the design decisions behind the `WebApp` schema.
  3. [`03-scaffold-with-kubebuilder.md`](./docs/03-scaffold-with-kubebuilder.md)
     — install Kubebuilder, scaffold the project, generate the CRD YAML and
     RBAC from the Go markers.
  4. [`04-api-types-and-crd.md`](./docs/04-api-types-and-crd.md) — walks
     through `webapp_types.go` field by field and the generated CRD manifest
     it produces.
  5. [`05-controller-reconcile.md`](./docs/05-controller-reconcile.md) — the
     Reconcile loop in `webapp_controller.go`: owner references, `CreateOrUpdate`,
     status updates, why there's no finalizer.
  6. [`06-build-push-deploy.md`](./docs/06-build-push-deploy.md) — build the
     operator image, push to ACR, deploy the manager + CRD + RBAC to the
     cluster.
  7. [`07-test-and-observe.md`](./docs/07-test-and-observe.md) — apply a
     `WebApp`, watch the operator create/heal the Deployment and Service,
     edit and delete it.
  8. [`08-cleanup.md`](./docs/08-cleanup.md) — tear down the operator and the
     cluster.

## Prerequisites

- An Azure subscription and `az login` already done (`az account show` to
  confirm).
- `terraform`, `kubectl`, `helm` — already used elsewhere in this repo.
- `go` 1.23+, `docker` (or another OCI builder), and the `kubebuilder` CLI —
  new for this folder, installed in step 3.
