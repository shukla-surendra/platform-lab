05 · AND vs OR selectors

The idea: One extra "-" in the YAML turns a narrow rule (AND) into a much wider one (OR).

Self-contained: this example creates its own namespaces and needs nothing from the others.

                                AND policy   OR policy
np-05-other/client  (role=client)   ✓           ✓
np-05-other/random  (no role)       ✗           ✓   any pod in np-05-other
np-05-app/local     (role=client)   ✗           ✓   role=client in np-05-app

   np-05-app/local -> web:80                    ok        ok        ✓

How the policy works

  • AND: namespaceSelector and podSelector are in the same list item. A pod must match both.
  • OR: each selector is its own list item (its own -). A pod matching either one gets in.
  • In the OR form, a podSelector on its own means "pods with this label in the policy's own namespace". That's why np-05-app/local gets in.
  • Both files use the same policy name, so applying the OR file replaces the AND one.

policy-and.yaml

# AND: ONE list item holding both selectors.
# Allows pods that are in namespace np-05-other AND have label role=client.
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: web-allow
  namespace: np-05-app
spec:
  podSelector:
    matchLabels: {app: web}
  policyTypes: [Ingress]
  ingress:
    - from:
        - namespaceSelector:                       # one "-" ...
            matchLabels: {kubernetes.io/metadata.name: np-05-other}
          podSelector:                             # ... no "-" here: same item, so AND
            matchLabels: {role: client}

policy-or.yaml

# OR: TWO list items. Only difference from policy-and.yaml is the extra "-" before podSelector.
# Allows (any pod in namespace np-05-other) OR (pods with role=client in THIS namespace, np-05-app).
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: web-allow
  namespace: np-05-app
spec:
  podSelector:
    matchLabels: {app: web}
  policyTypes: [Ingress]
  ingress:
    - from:
        - namespaceSelector:                       # item 1
            matchLabels: {kubernetes.io/metadata.name: np-05-other}
        - podSelector:                             # item 2 (note the "-"): OR
            matchLabels: {role: client}

Compare the two files with diff policy-and.yaml policy-or.yaml. The only real difference is one -.
