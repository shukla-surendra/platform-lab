07 · Lock down a three-tier app

The idea: Combining deny-all, DNS, and per-tier allow rules leaves only the app's intended paths open.

Self-contained: this example creates its own namespaces and needs nothing from the others.

np-07-outside/client ──▶ web:80 ──▶ api:80 ──▶ db:6379

every other path is blocked, in both directions

How the policy works

  • Policy 1 denies both ingress and egress for every pod in the app namespace.
  • Policy 2 allows DNS for every pod (see example 06 for why).
  • Policies 3–5 open exactly one path each. A connection needs egress allowed on the sender and ingress allowed on the receiver: for example, web → api needs web's egress rule (policy 3) and api's ingress rule (policy 4).
  • web → db is blocked: web can only reach the database through api.

policy.yaml

# Full lockdown of the three-tier app: only  outside/client -> web:80 -> api:80 -> db:6379  is allowed.
# Five policies in one file, separated by "---".

# 1. Default: nothing in or out of any pod in np-07-app
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: {name: default-deny-all, namespace: np-07-app}
spec:
  podSelector: {}
  policyTypes: [Ingress, Egress]
---
# 2. Every pod may use cluster DNS
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: {name: allow-dns, namespace: np-07-app}
spec:
  podSelector: {}
  policyTypes: [Egress]
  egress:
    - to:
        - namespaceSelector: {matchLabels: {kubernetes.io/metadata.name: kube-system}}
          podSelector: {matchLabels: {k8s-app: kube-dns}}
      ports: [{protocol: UDP, port: 53}, {protocol: TCP, port: 53}]
---
# 3. web: in from the outside client on 80, out to api on 80
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: {name: web, namespace: np-07-app}
spec:
  podSelector: {matchLabels: {app: web}}
  policyTypes: [Ingress, Egress]
  ingress:
    - from:
        - namespaceSelector: {matchLabels: {kubernetes.io/metadata.name: np-07-outside}}
      ports: [{protocol: TCP, port: 80}]
  egress:
    - to:
        - podSelector: {matchLabels: {app: api}}
      ports: [{protocol: TCP, port: 80}]
---
# 4. api: in from web on 80, out to db on 6379
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: {name: api, namespace: np-07-app}
spec:
  podSelector: {matchLabels: {app: api}}
  policyTypes: [Ingress, Egress]
  ingress:
    - from:
        - podSelector: {matchLabels: {app: web}}
      ports: [{protocol: TCP, port: 80}]
  egress:
    - to:
        - podSelector: {matchLabels: {app: db}}
      ports: [{protocol: TCP, port: 6379}]
---
# 5. db: in from api on 6379, nothing out (besides DNS from policy 2)
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: {name: db, namespace: np-07-app}
spec:
  podSelector: {matchLabels: {app: db}}
  policyTypes: [Ingress]
  ingress:
    - from:
        - podSelector: {matchLabels: {app: api}}
      ports: [{protocol: TCP, port: 6379}]

Try this

List the policies with kubectl get netpol -n np-07-app, then read one in plain words with kubectl describe netpol api -n np-07-app.
