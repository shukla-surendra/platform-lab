04 · Allow traffic from another namespace

The idea: A policy can let in traffic from a whole namespace, selected by its labels.

Self-contained: this example creates its own namespaces and needs nothing from the others.

np-04-trusted/client   ──✓──▶ np-04-app/web:80
np-04-untrusted/client ──✗──▶ np-04-app/web:80

   np-04-untrusted/client -> web:80             BLOCKED   BLOCKED   ✓

How the policy works

  • namespaceSelector selects namespaces by label, and allows every pod in them.
  • Kubernetes automatically labels every namespace with kubernetes.io/metadata.name: <its name>, so you can select one by name without adding labels.
  • Both clients are identical pods with the same labels. Only their namespace differs.
  • A common real use: allow traffic from your ingress controller's namespace (for example ingress-nginx).

policy.yaml

# web accepts traffic only from pods in namespace np-04-trusted.
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: web-allow-trusted-namespace
  namespace: np-04-app
spec:
  podSelector:
    matchLabels: {app: web}
  policyTypes: [Ingress]
  ingress:
    - from:
        - namespaceSelector:
            matchLabels:
              # Kubernetes adds this label to every namespace automatically
              kubernetes.io/metadata.name: np-04-trusted

Try this

See the automatic labels with kubectl get ns --show-labels | grep np-04.
