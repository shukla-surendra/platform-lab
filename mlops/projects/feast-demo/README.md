# Feast feature store demo

Runnable Feast quickstart: define features once, retrieve a point-in-time
correct training set from the offline store, train a small model,
materialize features into the online store, and serve a prediction from
it. Companion to
[`docs/tools/feast/README.md`](../../docs/tools/feast/README.md).

## Layout

```
feature_repo/
  feature_store.yaml        <- local config: file registry, sqlite online store
  feature_definitions.py    <- Entity, FeatureView, FeatureService (trimmed
                                down from feast init's full generated scaffold)
  data/
    driver_stats.parquet    <- sample data (Feast's own driver-stats dataset)
feast_quickstart.ipynb      <- the walkthrough notebook
```

## Setup (uv)

```bash
cd projects/feast-demo
uv sync
```

## Run it

```bash
uv run jupyter notebook feast_quickstart.ipynb
```

Or headlessly:

```bash
uv run jupyter nbconvert --to notebook --execute --inplace feast_quickstart.ipynb
```

This registers the feature definitions (`feast apply`), pulls historical
features for training, materializes them into a local SQLite online
store, and serves a prediction using online feature lookups — all steps
run for real, not mocked.

`feature_repo/data/registry.db` and `feature_repo/data/online_store.db`
are generated by running the notebook (gitignored) — delete them to reset
to a clean state.
