Reading the arrows

Solid — fixed edge START→agent and tools→agent always run. No decision is made here.
Dashed — conditional edge tools_condition picks the destination fresh, every time agent runs.

What actually happens, node by node

  1. START → agent. Every run begins here — the system prompt gets prepended, the full message history goes to the model.

  2. agent decides. The model either answers in plain text, or requests one or more tool calls (create_plan, check_memory, run_command, ...).

  3. tools_condition reads that decision. A tool call present → "tools". Nothing to call → END, immediately.

  4. tools executes. ToolNode runs the real Python function(s) behind whichever tool(s) were requested — a live subprocess.run, a file write, or an interrupt() pausing for human approval.

  5. Back to agent, always. The result feeds back in as a message, and the model decides again — call another tool, or stop. This is the one cycle that makes multi-step, create_plan-driven work possible: the loop runs as long as tools_condition keeps saying "tools," capped only by RECURSION_LIMIT in main.py.
