Building ways(n), one stair at a time

Different angle from the tree diagram: instead of showing the finished shape, this walks through constructing each answer’s full list by hand, literally copying the two lists before it. Indigo = copy ways(n−1)’s list, stamp +1 on every copy. Ochre = copy ways(n−2)’s list, stamp +2 on every copy. Nothing else ever happens.

0

ways(0) = 1 — given directly, not built

You’re already standing at the top with zero stairs to climb. There’s exactly one way to do that: take no moves at all. There’s no smaller case to build this from — ways(−1) and ways(−2) don’t exist. That’s exactly why the code has to hand this answer over directly instead of computing it.

  • (the empty path — no moves)
1

ways(1) = 1 — given directly, not built

One stair, one way: a single +1. This has to be given directly too — if it tried to build itself from ways(0) + ways(−1), it would need ways(−1), which is meaningless. So n == 1 gets caught by the same base-case check as n == 0, before the recursive line ever runs.

  • 1
2

ways(2) = ways(1) + ways(0) = 1 + 1 = 2 — the first one actually built

This is the smallest n where the recursive line runs at all — and both pieces it needs, ways(1) and ways(0), are real, valid, already-answered cases. No negative index ever gets asked for.

copy ways(1), stamp +1

  • 1+1

copy ways(0), stamp +2

  • 2 (nothing to copy — ways(0) is the empty path)
3

ways(3) = ways(2) + ways(1) = 2 + 1 = 3

copy ways(2), stamp +1

  • 1+1+1
  • 2+1

copy ways(1), stamp +2

  • 1+2
4

ways(4) = ways(3) + ways(2) = 3 + 2 = 5

copy ways(3), stamp +1

  • 1+1+1+1
  • 2+1+1
  • 1+2+1

copy ways(2), stamp +2

  • 1+1+2
  • 2+2
5

ways(5) = ways(4) + ways(3) = 5 + 3 = 8

copy ways(4), stamp +1

  • 1+1+1+1+1
  • 2+1+1+1
  • 1+2+1+1
  • 1+1+2+1
  • 2+2+1

copy ways(3), stamp +2

  • 1+1+1+2
  • 2+1+2
  • 1+2+2
6

ways(6) = ways(5) + ways(4) = 8 + 5 = 13

Same construction — copy all 8 of ways(5)’s sequences and stamp +1 on each, copy all 5 of ways(4)’s and stamp +2 on each. 13 sequences, built exactly the same way as every step above. This is where writing them all out stops being useful — you already know how the list would look if you wrote it.

7

ways(7) = ways(6) + ways(5) = 13 + 8 = 21

21 sequences. Still nothing new — copy, stamp, count. This is the trust you’re being asked to extend to ways(n−1) and ways(n−2) for any n: not blind faith, just the same copy-and-stamp operation you’ve now watched run six times in a row.

A list for ways(n) is never invented from scratch. It’s always ways(n−1)’s list, copied, with +1 stamped on the end of every copy, sitting next to ways(n−2)’s list, copied, with +2 stamped on the end of every copy. Stamping the same move onto every item in a list doesn’t add or remove items — so the size of each copied block never changes. That’s the entire mental model: ways(n) = ways(n−1) + ways(n−2) is just “how big is this copy, plus how big is that copy,” all the way down to the two lists — ways(0) and ways(1) — that were never copies of anything at all.
